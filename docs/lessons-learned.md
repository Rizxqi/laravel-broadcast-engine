# 🎓 Lessons Learned

## Key Takeaway

How to integrate multiple services (Laravel, Liquidsoap, Icecast) into a single cohesive ecosystem via Docker. In particular, how Laravel can **generate configuration for another service** (`radio.liq`) programmatically — a pattern that's very useful for infrastructure-as-code. Also learned about HTTP streaming protocols and how audio players (VLC, STB) communicate via HTTP Range requests.

## What Would Be Done Differently

- **Dockerize Laravel as well** — Currently Laravel runs on the host while Icecast & Liquidsoap run in Docker, creating awkward path inconsistencies.
- **Implement Liquidsoap auto-restart** via Laravel (executing a Docker command) instead of requiring operators to manually restart it after every playlist change.
- **Build a test suite** from the start, especially for `LiquidsoapConfigService` and the streaming logic.
- **Use Liquidsoap's telnet interface** for hot-reloading playlists without restarting the container.

## New Skills Gained

- Audio streaming protocols (Icecast, SHOUTcast, HTTP Range streaming)
- Liquidsoap scripting language for audio pipelines
- Multi-container Docker orchestration with shared volumes
- FFmpeg CLI for audio/video conversion
- Laravel RBAC implementation (Policy + Role system)
- HTTP streaming with chunked responses and Range header support

## Most Challenging Part

**Synchronizing paths between Windows (dev) and the Linux container (Docker).** Files generated by Laravel at `D:\Kuliah\project-root\music\` had to be readable as `/music/` inside the Liquidsoap container. This was resolved with environment variables for all paths (`LIQUIDSOAP_M3U_PATH`, `LIQUIDSOAP_MUSIC_BASE_PATH`) and careful Docker volume mounting. Also frustrating was Icecast's **inconsistent response format** (object vs. array depending on the number of sources), which was resolved by normalizing the response in code.
